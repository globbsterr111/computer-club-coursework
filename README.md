# Информационная система компьютерного клуба

Курсовой проект Г. А. Павловского, группа 324. Приложение позволяет найти свободный компьютер, посмотреть тарифы, провести игровой сеанс и зарегистрировать оплату. Гость просматривает каталог, клиент видит свои сеансы, администратор ведёт журнал и справочники.

## Состав проекта

| Путь | Что находится в папке или файле |
| --- | --- |
| `src/Club/Club.slnx` | Решение Visual Studio. Проект запуска — **Club**. |
| `src/Club/Club.csproj` | Файл проекта приложения. Именно его передают команде `dotnet run --project`. |
| `src/Club/Views`, `Services`, `Data`, `Models` | Интерфейс и диалоги, правила операций и входа, доступ к базе, модели таблиц. |
| `src/Запустить_клуб.cmd`, `src/Start-Club.ps1` | Запуск двойным щелчком и сценарий настройки. |
| `database` | `01_БД.sql` создаёт таблицы и учебные данные. `02_Сеансы.sql` добавляет расчёт стоимости и операции с сеансами. |
| `docs` | Пояснительная записка, презентация, диаграммы, каталог и протокол. |
| `resources/sources.txt` | Источники проекта и происхождение графических материалов. |
| `tests` | Консольные проверки паролей и SQL-сценарии для отдельной базы. |

## Что понадобится

- Windows и **.NET 10 SDK**. Команда `dotnet --list-sdks` должна показать установленную версию `10.0.x`.
- Запущенный Microsoft SQL Server с доступным экземпляром. Для ручной настройки удобно использовать SQL Server Management Studio (SSMS). SSMS — программа управления. Саму базу обслуживает служба SQL Server.
- Для запуска через IDE — Visual Studio с поддержкой .NET 10. Первая сборка восстанавливает пакеты из NuGet.
- В проекте используются **C# / .NET 10, Avalonia 11.3.22 и EF Core 10.0.14**. Если база уже подготовлена, нужны разрешения на операции приложения. Для автоматического создания базы дополнительно нужны права создания базы и её объектов.

## Вариант 1. Запуск двойным щелчком

1. Распакуйте архив целиком. Откройте `src` и дважды щёлкните `Запустить_клуб.cmd`.
2. Дождитесь окончания сборки и открытия окна «Компьютерный клуб». Каталог и тарифы доступны без входа.
3. Если у вас другой экземпляр SQL Server, заранее настройте `src/Club/connection.txt` по инструкции ниже.

`Запустить_клуб.cmd` открывает PowerShell и находит `Start-Club.ps1` в той же папке. Если сценарий завершится с ошибкой, консоль останется открытой, чтобы можно было прочитать сообщение.

`Start-Club.ps1` проверяет .NET SDK, настройки SQL Server и собирает приложение. Если в настройках явно указан сервер, сценарий использует этот адрес. Без локальной настройки он берёт адрес из примера и пробует также стандартный локальный экземпляр и LocalDB. Затем сценарий проверяет базу `computer_club_db`. Если база отсутствует или пуста, он подготавливает её скриптами 01 и 02. Готовую схему использует как есть. Если находит неполную или отличающуюся схему, сообщает об этом. Сценарий защищает от одновременных запусков из одной папки и сообщает, если окно клуба из этой сборки уже открыто. Учётного администратора этот запуск не создаёт.

## Вариант 2. База вручную и запуск из Visual Studio

1. В SSMS подключитесь к **Database Engine**. Запомните имя сервера из окна подключения. Если подходящая база `computer_club_db` уже создана, переходите к шагу 4.
2. В обозревателе объектов нажмите правой кнопкой **Databases → New Database**. Создайте пустую базу `computer_club_db`.
3. Откройте `database/01_БД.sql`. В списке баз над редактором выберите **computer_club_db** и выполните весь файл кнопкой **Execute**. Затем тем же способом выполните `database/02_Сеансы.sql` в той же базе. Скрипт 01 рассчитан на пустую базу. Если его запуск прервался, сначала проверьте ошибку и состояние базы.
4. В Проводнике откройте `src/Club`, где лежит `Club.csproj`. Сделайте копию `connection.example.txt`, назовите её **connection.txt** и откройте в Блокноте. Пример для локального SQL Server Express с входом Windows:

   ```text
   Server=.\SQLEXPRESS;Database=computer_club_db;Integrated Security=True;TrustServerCertificate=True;
   ```

   Замените значение `Server=` на имя экземпляра из SSMS. В `Database=` укажите своё имя базы. Автоматический сценарий рассчитан на имя `computer_club_db`. Включите в Проводнике показ расширений: итоговое имя должно быть **connection.txt**. При сборке проект копирует этот файл рядом с приложением. Если задана переменная `CLUB_CONNECTION`, приложение использует её в первую очередь. Локальный `connection.txt` исключён из Git.
5. Откройте `src/Club/Club.slnx` в Visual Studio. Назначьте **Club** запускаемым проектом и нажмите **F5** или **Ctrl+F5**. После изменения файла подключения завершите предыдущий запуск и пересоберите проект. Если вместо Visual Studio используете PowerShell, из папки `Coursework` выполните `dotnet run --project .\src\Club\Club.csproj`.

## Создание первого администратора

Скрипты базы создают роли, справочники и учебные данные. Учётную запись `admin` создают отдельной командой. Сделайте это для той же базы, в которой будете показывать проект.

1. Настройте `src/Club/connection.txt` и закройте приложение. Если оно запущено из Visual Studio, нажмите **Остановить отладку**.
2. Откройте папку **Coursework** в Проводнике, где видны `README.md` и папки `src`, `database`. В адресной строке Проводника наберите **powershell** и нажмите **Enter**. Так PowerShell откроется в нужной папке.
3. Вставьте весь блок и нажмите **Enter**. Когда появится запрос, введите свой пароль длиной от 12 символов. Ввод скрыт.

```powershell
$project = Join-Path (Get-Location).Path 'src\Club\Club.csproj'
if (-not (Test-Path -LiteralPath $project -PathType Leaf)) {
    throw 'Откройте PowerShell в папке Coursework, где лежит README.md.'
}

$password = Read-Host 'Придумайте пароль для admin, минимум 12 символов' -AsSecureString
try {
    if ($password.Length -lt 12) { throw 'Пароль должен содержать минимум 12 символов.' }

    $env:CLUB_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
    dotnet run --project "$project" -- --create-admin admin
    if ($LASTEXITCODE -ne 0) {
        throw 'Администратор не создан. Причина указана выше.'
    }
    Write-Host 'Администратор admin создан.'
} finally {
    Remove-Item Env:CLUB_ADMIN_PASSWORD -ErrorAction SilentlyContinue
    $password.Dispose()
}
```

`CLUB_ADMIN_PASSWORD` передаёт придуманный пароль только процессу создания записи. К входу в SQL Server он отношения не имеет. После `--` идут аргументы приложения: `--create-admin admin` означает создать администратора с логином **admin**. В базе сохраняется хеш пароля с индивидуальной солью. После завершения блок удаляет переменную из PowerShell. Запустите клуб обычным способом и войдите под логином `admin` с выбранным паролем. На одну базу достаточно одного первоначального создания записи.

## Как выдать логин клиенту

1. Войдите как администратор. В разделе **Клиенты** выберите существующего клиента или нажмите **Добавить клиента**. Для новой записи укажите фамилию, имя и уникальный телефон.
2. Перейдите в **Учётные записи → Создать запись клиента**. Выберите клиента, задайте уникальный логин и пароль от 12 символов. Нажмите **Подтвердить**. Один клиент может быть связан с одной учётной записью.
3. Нажмите **Выйти** и войдите под новым логином. Убедитесь, что есть раздел **Мои сеансы**. Список будет пустым, пока для этого клиента нет сеансов.

## Проверки проекта

Из корня проекта запустите `dotnet run --project .\tests\Club.Tests\Club.Tests.csproj`, чтобы выполнить семь проверок хеширования паролей. SQL-проверки выполняются **в отдельной пустой базе** с именем на `ClubStage7Test_`. В ней последовательно выполните `01_БД.sql`, `02_Сеансы.sql`, затем `tests/03_Проверки.sql`. Тест последовательно меняет данные и проводит учебные оплаты, поэтому запускать его в рабочей базе нельзя.

## Если запуск не получился

| Сообщение или признак | Что проверить |
| --- | --- |
| Не найден проект или указан неверный путь | Проверьте, что в PowerShell текущая папка — `Coursework`. Для `dotnet run --project` нужен `Club.csproj`. |
| Появилось `>>` | PowerShell ждёт окончания блока. После последней `}` нажмите Enter. При неполной вставке нажмите Ctrl+C и вставьте блок заново. |
| Не задана переменная CLUB_CONNECTION или connection.txt | Проверьте имя файла, включая расширение, и его расположение рядом с `Club.csproj`. После пересборки проверьте, что он есть рядом с `Club.exe` в папке сборки. |
| Сервер не найден или запрос не выполнен | Попробуйте подключиться в SSMS тем же способом. Сверьте имя сервера, имя базы и статус службы. Убедитесь, что оба скрипта выполнены именно в той базе, которую открывает приложение. |
| `Club.exe is being used` или клуб уже открыт | Закройте окно клуба или остановите отладку в Visual Studio. Затем повторите сборку или запуск. |
| Дублирующийся логин `admin` | Запись уже есть в выбранной базе. Войдите с ранее заданным паролем. Команда создания не сбрасывает существующий пароль. |
| Гость видит каталог, но не может вести сеансы | Войдите как администратор. Для клиента доступны просмотр и собственная история сеансов. |
